## 1. 项目一句话介绍

学涯（Orbit）是一个本地优先（Local-First）的 AI 学习 Agent：用户导入资料或提出学习目标后，系统构建学习路线，由 AI 导师以苏格拉底式对话主动展开连续教学，并根据每一次回答动态调整路线与教学策略。

备选（更短）：

> 学涯是一个以苏格拉底式对话学习为核心、支持用户自主构建学习路径的本地优先 AI 学习 Agent。

---

## 2. 项目背景

大模型普及后，大量"AI 学习产品"涌现，但多数产品的形态是"问答框 + 题库"：AI 负责直接给答案，练习负责判对错，两者都不参与"教"的过程。与此同时，学习者手上积累了越来越多的真实资料（课件、论文、PDF、网页），却缺少工具把它们组织成一条可以走下去的学习路径。

学涯针对这一背景做了一个不同的尝试：**让 AI 承担"教师"的角色，而不是"答案机"的角色**。系统围绕"来源 → 综合 → 路线 → 学习 → 提问 → 诊断 → 调整 → 复习"这一完整闭环构建，对话是课堂，路线会随学习者的表现实时改变。

（证据：README.md；docs/ARCHITECTURE.md 第 4 节学习闭环）

---

## 3. 用户痛点

1. **AI 只是问答框。** 用户问一句、AI 答一句，AI 生成的是答案而不是理解；学习者看完答案仍然不会。
2. **学习路径碎片化。** 资料、课程、练习分散在不同工具里，学习者要自己承担"下一步学什么"的决策负担。
3. **练习与内容割裂。** 做题做对了不知道下一步去哪，做错了没有人解释"为什么错、该怎么补"。
4. **自有资料难以课程化。** 用户拥有大量 PDF / 文档 / 网页，却只能做摘要或全文问答，无法变成有顺序、有诊断的教学过程。
5. **学习软件退化成题库。** 学习体验被压缩成刷题和分数，教学互动消失。
6. **隐私与掌控权。** 学习数据、笔记和资料是高度私人的内容，云端优先的产品要求用户先交出自己的数据才能开始学习。

## 4. 产品定位

- 学涯**不是**刷题 App，也**不是** AI 问答壳。测验（Quiz）只是阶段性检查与教学工具之一，不是产品主体。
- 学涯是**一个以苏格拉底式对话学习为核心、支持用户自主构建学习路径的 AI 学习 Agent**。
- 课堂是对话本身：用户进入知识节点后，Agent 主动开启教学，通过讲解、提问、追问、提示、类比、反例等方式连续教学，依据用户回答动态调整策略，在后台积累掌握度证据，并自然推进后续知识点。
- 架构上采用 **Local-First**：账号不是使用前提，不注册即可完整本地学习；登录后获得同步、Cloud AI、跨设备、云端备份等增强能力。

（证据：ARCHITECTURE_BOUNDARIES.md；audit/competition-convergence/COMPETITION_CONVERGENCE_REPORT.md 第 1 节）

## 5. 核心功能

### 5.1 对话式学习课堂（Conversation-first）

- 点击"开始学习"后，本地核心创建 `LearningSession`，并由 Agent **主动发出开场教学回合**（opening turn），学习者未输入前教学已开始。
- 学习界面以对话流为主体；原来的静态课文降级为可折叠的"本节概要"；测验卡片收在可选的「阶段检查」开关之后；学完后以「完成本节」收尾。
- AI 不可用时本地学习不阻断：返回明确标注来源的降级开场，绝不伪装成真实 AI。

（证据：COMPETITION_CONVERGENCE_REPORT.md §2.1；src-tauri/src/ai/prompts.rs `TUTOR_OPENING_V1_SYSTEM`；src/components/learning/LearningScreen.tsx）

### 5.2 动态学习路线

- 用户输入目标（可选择学习深度、接触程度），系统生成学习路线；可导入本地资料（Markdown / PDF / DOCX / HTML / 纯文本 / URL），路线基于真实资料规划。
- 答错客观题、或导师在对话中诊断出误解时，系统会在路线中**自动插入加练/复习节点**，并在首页提示条和对话中同时解释"为什么路线变了"；路线调整按知识点幂等，重启后依然保持。
- 复习到期时间驱动路线上的待复习提示。

（证据：docs/ARCHITECTURE.md §4；src-tauri/migrations/0002_learning_loop.sql `adaptation_events`；src-tauri/tests/learning_loop.rs）

### 5.3 用户资料成为课程

- 资料经 解析 → 分块 → 向量化 → 索引 的本地管线进入学习库；embedding 缓存按"文本+提供方+模型+维度"做 SHA-256 寻址，避免重复计算。
- 检索为 FTS5 全文 + 向量混合检索（RRF 融合），按路线/资料/知识点在 SQL 层过滤：**显式选择的资料构成封闭检索边界**，一条路线不会串用另一条路线的资料，空结果不会静默退化为全库搜索。
- 导师回答中的引用标记 `[C1] [C2]` 在 Rust 侧映射回真实资料片段，前端可展开"依据"查看原文。

（证据：docs/ARCHITECTURE.md §5.3；ARCHITECTURE_BOUNDARIES.md 检索边界条款；src-tauri/tests/retrieval.rs）

### 5.4 自由作答的 AI 评阅

- 简答题提交后不会被丢下：可点「让 Orbit 评阅这段作答」，评语写进对话、证据记入掌握度。
- 客观题本地即时判分；主观题不在本地伪造自动判分。

（证据：README.md；docs/ARCHITECTURE.md §4 第 4 步）

### 5.5 资料库与设置

- 资料库：列出路线可引用的全部来源，支持重建索引与删除。
- 设置：AI 来源（Cloud / BYOK / 离线）、云账号与设备管理、同步开关与手动同步、BYOK 服务商增删改测、网页搜索配置；密钥字段只写不读，永不回显。

（证据：docs/ARCHITECTURE.md §8）

### 5.6 联网搜集资料（可选）

- 开启后由后端调用网页搜索（支持 Brave 密钥或已配置的 Step 搜索服务），可把命中的网页作为真实资料导入后再规划路线；AI 辅助生成检索词时最多筛选三条实际候选，网页内容一律按不可信内容处理。

（证据：docs/OOBE_FLOW.md「检索」一节）

## 6. 核心创新

### 6.1 苏格拉底式学习 Agent（教学动作体系）

Agent 不直接给答案，而是每回合从 **13 种教学动作**中选择一种：Explain（讲解）、Ask（提问）、Probe（追问诊断）、Hint（提示）、Example（举例）、Counterexample（反例）、Challenge（挑战）、Reflect（反思）、Summarize（总结）、Transition（过渡）、Exercise（练习）、Quiz（测验）、CompleteConcept（完成概念）。

配套机制：

- 提示词层面明确要求"先问后讲、先提示后给答案、先追问后纠正"，禁止把每个问题都变成选择题，禁止"长篇讲授 + 立即测验"。
- 每个回合同时产出结构化诊断（误解类型、置信度、严重度）与内部掌握度增量 `masteryDelta`（限定 ±0.25，只作证据、从不作为分数展示）。
- 学习者状态推断枚举：理解、部分理解、误解、猜测、不确定、需要例子、需要前置知识、深度理解。
- `LearningTurn / AgentAction / LearnerResponse / ConceptState / MasteryEvidence` 已提升为一等领域概念，由 `TutorService::turns` 从持久化消息组装，对话是领域对象而非平面日志。

（证据：src-tauri/src/domain/learning.rs；src-tauri/src/ai/prompts.rs `TUTOR_V1_SYSTEM`；COMPETITION_CONVERGENCE_REPORT.md §2.2–2.3）

### 6.2 动态学习路线

路线不是固定教材目录：它围绕知识目标与掌握证据组织，答错或被诊断出误解时按统一策略（Diagnosis → AdaptationPolicy → AdaptationDecision → AdaptationService）改写路线，并保留完整的"为什么改"事件日志。

（证据：docs/ARCHITECTURE.md §5.5）

### 6.3 Local-First 学习架构

重要的学习数据与学习逻辑全部留在本地 SQLite：课程、会话、路线、掌握度、诊断、检索、向量索引均在本地闭环；网络中断、账号失效、云端不可用时本地学习完整可用。

（证据：RUNTIME_BOUNDARY.md §2 已验证的本地路径）

### 6.4 用户自己的资料成为课程

资料通过检索与向量能力成为教学上下文：导师的每个论断可以落到真实资料片段上，引用可溯源、边界可隔离；资料不足时如实声明 `insufficient_source`，不把通用知识伪装成"你的资料说的"。

（证据：src-tauri/src/ai/prompts.rs grounding 规则；AI_INTEGRATION_MATRIX.md §4）

### 6.5 AI Gateway + BYOK 双轨

- **BYOK**：用户自配 OpenAI 兼容服务（同时支持 Chat Completions 与 Responses 两种协议，自动探测端点能力并缓存），密钥写入操作系统钥匙串，前端永不可见。
- **Cloud AI Gateway**：云端以逻辑模型名（verruckt-fast / standard / reasoning / embedding）屏蔽上游差异，统一做鉴权、配额、限流、流式转发与用量记账。
- 两种路径实现同一组 `ChatProvider / EmbeddingProvider` trait；离线模式用确定性 MockProvider，且永远标注为离线/模板输出，绝不伪装真实 AI。

（证据：AI_INTEGRATION_MATRIX.md；cloud/README.md「Official AI gateway」）

## 7. 技术架构

### 7.1 总体分层

| 层 | 职责 | 实现 |
| --- | --- | --- |
| 前端 WebView | 路线、学习、资料、设置界面；手势与动效 | React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + zustand |
| IPC 边界 | 唯一出口 `api.ts`，全部命令类型化封装，前后端契约测试保证一致 | Tauri 2 Commands（约 59 条） |
| Rust 本地核心 | 课程/学习/测验/导师/摄入/检索/任务等服务层，领域规则，SQLite 仓储 | src-tauri（lib: verruckt_lib） |
| 数据 | 本地 SQLite（7 个迁移版本），离线可用 | sqlx + SQLite（含 FTS5） |
| AI 提供方层 | Offline / BYOK / Cloud 三模式，显式策略 | ai/ 模块 + registry |
| 向量引擎 | 独立 crate，Exact + 自研 HNSW，WAL + 分代段文件持久化 | crates/verruckt-vector |
| Verruckt Cloud | 账号/设备/权益/同步/存储/AI 网关/配额 | cloud/ Rust workspace（axum，4 个 crate）+ PostgreSQL + MinIO/S3 + Docker |

（证据：docs/ARCHITECTURE.md §1；src-tauri/migrations/；cloud/README.md）

### 7.2 架构纪律（可写进申报书的工程要点）

- **Rust 拥有真相**：前端不计算进度、掌握度或路线调整，只渲染后端返回。
- **契约测试**：`ipc-contract.test.ts` 解析 `api.ts`、`lib.rs` 与假后端，保证每条命令三方一致，重命名会在构建期而非运行期爆炸。
- **不可信内容边界**：导入资料只以 `UNTRUSTED REFERENCE CONTENT` 区段进入提示词，永远进不了 system 指令；提示注入有专门测试。
- **密钥边界**：BYOK 密钥进 OS 钥匙串；Cloud 访问令牌只存在于 Rust 内存，刷新令牌进钥匙串；错误信息序列化前做密钥脱敏。
- **URL 摄入安全**：拒绝 localhost/内网/链路本地/云元数据地址与 `file:`/`ftp:` 协议，每次跳转前重新校验 DNS（防 SSRF）。
- **向量空间不混用**：embedding 维度来自实测并持久化，维度变化强制重建索引，而不是静默混合向量空间。

（证据：docs/ARCHITECTURE.md §5、§7；src-tauri/src/ingest/url_security.rs；src-tauri/src/ai/prompts.rs 测试）

### 7.3 自研向量引擎（Verruckt Vector Engine）

- 桌面级嵌入式向量引擎：面向约 1k–100k chunk 规模，非 SaaS 级。
- Exact（精确）与 HNSW（近似）双算法；HNSW 为独立实现（ChaCha8 确定性分层、可调 M/ef 参数、启发式邻居选择），非封装第三方库。
- 崩溃安全：先写 WAL 再改内存，manifest 原子提交，撕裂的 WAL 尾部在恢复时截断。
- 与桌面 RAG 管线打通：SQLite 仍是默认与权威后端，自研引擎为可选后端（`VERRUCKT_VECTOR_BACKEND=verruckt`）；切换后端不增加任何 embedding 调用。
- 实测：30 条真实语料查询下三种后端 Top1 = 0.867、Recall@5/10 = 1.000 完全一致；10 万向量规模 Exact 端到端 p50 约 22ms；在 Recall@10 ≥ 0.95 约束下 HNSW 未出现可用交叉点，因此精确检索保持默认——这是基于基准证据的工程决策。

（证据：crates/verruckt-vector/README.md；docs/VECTOR_INTEGRATION_REPORT.md）

### 7.4 多 Agent 路线生成

路线生成采用两阶段：大纲 Agent 负责整体目标、章节依赖与节点顺序；每个节点的内容 Agent 独立生成讲解与配套题目，单节点失败隔离、可单独重试，不会在失败时填入伪装成 AI 的模板内容。进程级并发额度默认 4，可配置。

（证据：docs/MULTI_AGENT_GENERATION.md；src-tauri/tests/node_agents.rs）

## 8. AI 设计

### 8.1 三模式显式策略

| 模式 | 面向 | 提供方 | 失败行为 |
| --- | --- | --- | --- |
| Offline（全新安装默认） | 无账号纯本地 | 确定性 MockProvider | 输出明确标注离线/模板，绝不打真实 AI 标 |
| BYOK | 自带模型密钥 | OpenAI 兼容 Provider | 未配置时硬报错，不回退 Mock |
| Cloud | 登录 + 权益 + 配额 | CloudAiProvider → 云网关 | 未登录/无权益/无配额/云不可用时硬报错，不回退 BYOK 或 Mock |

`ORBIT_REQUIRE_AI=1` 时注册表层面强制真实提供方，离线模式直接返回显式错误。

（证据：AI_INTEGRATION_MATRIX.md §1；COMPETITION_CONVERGENCE_REPORT.md §2.4）

### 8.2 来源诚实（Provenance）

所有生成内容带来源标签：真实 BYOK 模型 `byok_*`、真实云模型 `official_*`、离线 mock `mock`、确定性模板 `deterministic`、基于资料的回答 `*_grounded`、纯模型知识 `model_knowledge`。UI 据此如实展示。

### 8.3 结构化输出与流式

- 课程计划、导师回合、自由作答评阅、测验生成、资料摘要均有独立 JSON schema 校验，失败自动修复重试一次。
- 流式导师使用纯文本协议 + 可选末行 `DIAGNOSIS: {...}`，展示前剥离诊断行并复用同一套路线调整管线。
- 引用标签 `[C1]` 只允许引用检索结果中出现过的标签，模型看不到数据库 ID。

（证据：docs/ARCHITECTURE.md §5.4；src-tauri/src/ai/structured.rs、schemas.rs）

## 9. Local-First 设计

- **账号不是前提**：安装 → 跳过登录 → 建课/导入资料 → 开始学习 → 导师开场 → 对话持久化 → 重启后路线、进度、引用、调整记录全部还在。全链路无任何必需的网络调用。
- **本地权威**：SQLite 触发器把权威写入记入 outbox 日志（同事务）；派生数据（分块、向量、FTS、缓存）永不同步，在每台设备本地重建。
- **同步是接力不是接管**：pull/push + 版本比对；`sync_apply_guard` 防止拉取的数据回流 outbox；冲突时保留本地行并记录服务端载荷，绝不静默覆盖学习进度；墓碑删除、幂等推送、断线重连均有测试覆盖。
- **文件走对象存储**：资料原件经预签名 URL 直传 MinIO/S3，双向 SHA-256 校验，内容寻址去重；同步只搬元数据，接收端本地重建索引。
- **降级是显式的**：云会话状态机 `Restoring | Authenticated | DegradedOffline | SignedOut`；网络故障进入 DegradedOffline，保留刷新令牌与最后已知权益，本地学习不受影响。

（证据：RUNTIME_BOUNDARY.md §2/§4；docs/ARCHITECTURE.md §5.6–5.8）

## 10. Cloud 设计

Verruckt Cloud 是**控制面**，不是学习引擎。职责严格限定为七项：账号/认证、会员/权益、设备管理、跨设备实体级增量同步、资料文件对象存储协调、官方 AI 网关、AI 用量/配额（外加 Docker 部署）。云端不导入任何本地学习服务，课程、掌握度、检索、诊断全部留在本地。

关键设计：

- **认证**：Argon2id 密码哈希；短期 HS256 访问令牌（默认 30 分钟）；256 位随机刷新令牌只存 SHA-256 哈希，旋转使用，旧令牌重用即吊销整个会话族。
- **权益**：计划/订阅/权益/用量计数四表模型；示例档位 free（无云同步、1 设备）与 pro（云同步、官方 AI、5 设备、月度 AI 额度、5 GiB 存储）；支付未接入，管理员 CLI 授权。
- **同步中继**：游标是持久 BIGSERIAL 而非时间戳；推送带版本冲突检测；`change_id` 幂等；所有查询按 `user_id` 隔离。
- **对象存储**：对象键为 `users/{user_id}/objects/{sha256}`，文件名永不做键；按用户 SHA-256 去重；云端不解析、不嵌入、不索引资料内容。
- **AI 网关**：逻辑模型映射上游真实模型；配额在调用上游前预占、确认用量后入账、失败流释放；额度耗尽在产生上游成本前返回 `402 ai_quota_exceeded`；**云端不持久化提示词、对话正文、检索片段或资料原文**。
- **安全**：CORS 默认拒绝、统一错误信封、上游密钥只走服务端环境变量/密钥文件、请求体与超时限制。
- **部署**：多阶段 Dockerfile（非 root 运行）+ Docker Compose（服务 + PostgreSQL + MinIO），命名卷持久化。

## 12. UI / 设计理念

- **设计先于实现**：视觉语言先在单文件原型中设计完成，应用是它的实现；原型是设计事实来源。
- **一条规则**："安静、温暖、纸面质感，动效承载意义"——每个动画都用于解释一次状态变化。明确排除通用组件库外观、仪表盘/侧边栏/卡片网格、把路线画成列表、ChatGPT 式聊天页。
- **主题模型**：主题 = 视觉母题（灯塔 Lighthouse / 浮标 Buoy）× 色彩方案（明 / 暗 / 跟随系统），两个维度正交、可独立持久化，共四种实装组合。
- **字体与色彩**：衬线展示字体让路线标题像"书的章节"；暖调低饱和色板，没有纯黑纯白。
- **手势引擎**：自研无框架滑动手势引擎（requestAnimationFrame 直写 transform，拖动不触发 React 重渲染；带阻尼与吸附的加权物理；滑动中途即可预览目标页面）；课程卡片到全屏的 clip 展开转场，支持 `prefers-reduced-motion` 降级。
- **首次引导（OOBE）**：三页完成——想学什么（输入框 + 六个候选）→ 接触程度与学习深度（两档滑块，可跳过）→ 添加资料（文件 / URL / 网页搜索）；账号可跳过。

（证据：docs/DESIGN_SYSTEM.md；docs/OOBE_FLOW.md；src/stores/themeStore.ts；docs/ARCHITECTURE.md §6）

## 15. 仍有限制（诚实清单）

1. **对话领域模型是视图而非独立表**：`LearningTurn` 等一等领域类型由持久化消息组装，独立 `learning_turns` 表是未来迁移项；这是为避免高风险迁移的竞赛期取舍。
2. **节点内容降级模板**：BYOK/Cloud 的路线规划失败会直接报错，但节点课文生成失败时仍可能使用明确标注为 `deterministic` 的本地模板，不冒充真实 AI。
3. **路线调整粒度**：导师目前通过"插入加练节点"调整路线，尚不能缩短、重排或改写当前课程的剩余步骤。
4. **自由作答不自动触发加练**：主观题评阅会记录证据并影响掌握度，但只有导师诊断会插入加练节点。
5. **联网搜集不做近重复去重与质量重排**。
6. **同步冲突**：保留本地并记录服务端载荷，UI 有提示，但尚无并排合并界面。
7. **Cloud 客户端一项并发测试在并行执行下存在时序 flake**（串行与隔离运行均通过），待排查。
8. **Android 未真机验证**；Windows MSI 包未产出（WiX 预发布号限制）。
9. **支付未接入**，Pro 权益由管理员 CLI 授予。
10. **本轮未做新的视觉重设计**，主题正交性保留，完整视觉回归矩阵未重跑。

（证据：COMPETITION_CONVERGENCE_REPORT.md §4；docs/ARCHITECTURE.md §9；cloud/README.md）

学涯（Orbit）尝试回答一个问题：如何让 AI 真正参与"教"的过程，而不仅是"回答"。它是一个本地优先的 AI 学习 Agent：用户导入自己的资料（PDF、文档、网页）或提出学习目标，系统将其构建为一条学习路线；进入知识节点后，AI 导师主动开场，通过讲解、提问、追问、提示、类比、反例等 13 种教学动作连续教学，并依据回答诊断误解、动态插入加练节点、调整后续路线。产品以对话为课堂，测验仅是可选的阶段检查。架构上，课程、会话、掌握度与检索全部在本机 SQLite 闭环，无需账号即可完整学习；登录后可启用跨设备同步与云端 AI 网关。系统同时支持用户自带模型密钥（BYOK），并对离线输出做明确标注，坚持来源诚实。
